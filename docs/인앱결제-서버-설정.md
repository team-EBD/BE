# 인앱 결제 — 서버 설정 (BE)

이 문서는 **백엔드가 필요로 하는 값**과 그 값을 어디서 얻는지, 어떻게 주입하고
어떻게 검증하는지만 다룬다.
스토어 콘솔에서 상품을 만들고 테스터를 등록하는 **클릭 단위 절차**는
FE 레포의 `docs/인앱결제-콘솔-설정-가이드.md` 에 있다.

---

## 1. 동작 개요

```
앱(FE)  ──결제──▶  Google Play / App Store
  │                        │
  │ 구매 토큰만 전달        │
  ▼                        │
BE  POST /v1/subscriptions/verify
  │                        │
  └──── 스토어 서버 API 로 직접 조회 ────▶ (진짜 결제인지, 언제 만료인지)
                           │
                           ▼
                    subscriptions 테이블에 스냅샷 저장
```

핵심 원칙: **클라이언트가 보낸 상태는 믿지 않는다.** FE 는 구매 토큰만 보내고,
"프리미엄인가"는 서버가 스토어에 물어본 결과로만 판단한다.

## 2. 환경변수

| 변수 | 필수 | 설명 |
| --- | --- | --- |
| `BILLING_BACKEND` | ✅ | `store`(실연동) / `mock`(로컬·테스트). **운영은 반드시 `store`** |
| `SUBSCRIPTION_PRODUCT_IDS` | ✅ | 콤마 구분. FE `src/features/billing/products.js` 와 같은 값 |
| `SUBSCRIPTION_REFRESH_MINUTES` |  | 캐시 재조회 주기(분). 기본 60 |
| `ANALYZE_DAILY_LIMIT_PREMIUM` |  | 구독자 분석 한도. 기본 `0` = 무제한 |
| `RECOMMEND_DAILY_LIMIT_PREMIUM` |  | 구독자 추천 한도. 기본 `0` = 무제한 |
| `GOOGLE_PLAY_PACKAGE_NAME` | ✅(A) | `com.eatlog` |
| `GOOGLE_PLAY_CREDENTIALS_JSON` | ✅(A) | 서비스 계정 JSON — **반드시 한 줄로 압축**(아래 ⚠️) |
| `GOOGLE_PLAY_CREDENTIALS_FILE` |  | 위 대신 파일 경로 (로컬 개발용) |
| `GOOGLE_PLAY_RTDN_SECRET` |  | RTDN 수신 URL 의 `?token=` 값 |
| `APP_STORE_ISSUER_ID` | ✅(i) | App Store Connect API 키의 Issuer ID (UUID) |
| `APP_STORE_KEY_ID` | ✅(i) | 10자 Key ID |
| `APP_STORE_PRIVATE_KEY` | ✅(i) | `.p8` 파일 내용(PEM). 개행은 `\n` 이스케이프 허용 |
| `APP_STORE_BUNDLE_ID` |  | 비우면 `APPLE_BUNDLE_ID` 재사용 |
| `APP_STORE_NOTIFICATION_SECRET` |  | App Store 알림 URL 의 `?token=` 값 |

(A) = Android 결제에 필요 / (i) = iOS 결제에 필요. 한쪽만 채우면 그 플랫폼만 동작한다.

> ⚠️ `BILLING_BACKEND=mock` 은 **어떤 문자열이든 유효한 구매로 인정한다**.
> 운영에 mock 이 올라가면 아무나 프리미엄을 켤 수 있다. 반대로 `store` 인데
> 자격증명이 비어 있으면 검증이 503 으로 실패할 뿐 권한이 새지는 않는다 —
> 그래서 배포 스펙의 기본값을 `store` 로 두었다.

## 3. 값을 어디서 얻나

### Google Play — 서비스 계정 JSON
1. Google Cloud Console → Play Console 과 연결된 프로젝트 → **IAM 및 관리자 → 서비스 계정**
2. 서비스 계정 생성 → **키 → 키 추가 → JSON** → 다운로드
3. Google Play Console → **사용자 및 권한** 에서 그 서비스 계정 이메일을 초대하고
   앱 권한 **"재무 데이터, 주문, 정기 결제 응답 설문지 보기"** 를 체크
4. Google Cloud Console → **API 및 서비스 → 라이브러리** → `Google Play Android Developer API` **사용 설정**
   (CI 에서 겪은 것과 같은 API — 프로젝트가 다르면 따로 켜야 한다)

> Firebase(스토리지·FCM) 서비스 계정과 **다른 계정**이다. 재사용하지 말 것.

### App Store — API 키(.p8)
1. App Store Connect → **사용자 및 액세스 → 통합 → App Store Connect API**
2. **키 생성** → 액세스 권한 `App 관리자` 이상 → `.p8` 다운로드 (**재다운로드 불가**)
3. 같은 화면의 **Issuer ID**(UUID)와 목록의 **Key ID**(10자)를 함께 보관

`.p8` 을 한 줄 환경변수로 바꾸기:

```bash
# bash
awk 'BEGIN{ORS="\\n"} {print}' AuthKey_XXXXXXXXXX.p8
```

## 4. 주입 (운영)

배포 스펙(`.github/workflows/deploy.yml`)이 cloudtype 앱의 환경변수를 통째로
덮어쓰므로, 값은 **GitHub Secrets** 에 넣고 스펙이 참조하게 한다.

레포 → Settings → Secrets and variables → Actions → New repository secret

- `GOOGLE_PLAY_CREDENTIALS_JSON` — JSON 을 **한 줄로 압축한 값** (여러 줄이면 배포 실패)
- `GOOGLE_PLAY_RTDN_SECRET` — 아무 임의 문자열(32자 이상 권장)
- `APP_STORE_ISSUER_ID`, `APP_STORE_KEY_ID`, `APP_STORE_PRIVATE_KEY`
- `APP_STORE_NOTIFICATION_SECRET`

시크릿을 추가한 뒤 `dev` 에 푸시하면 새 값으로 재배포된다.

## 5. 스토어 알림 (선택이지만 권장)

알림이 없으면 해지·환불·결제 실패를 **사용자가 앱을 열 때까지** 모른다.

- Play: Play Console → 수익 창출 → 수익 창출 설정 → **실시간 개발자 알림** →
  Pub/Sub 주제 생성 → 그 주제에 **푸시 구독** 추가 →
  엔드포인트 `https://<BE 도메인>/v1/subscriptions/notifications/google?token=<GOOGLE_PLAY_RTDN_SECRET>`
- Apple: App Store Connect → 앱 → **App 정보 → App Store 서버 알림** → 버전 **V2** →
  `https://<BE 도메인>/v1/subscriptions/notifications/apple?token=<APP_STORE_NOTIFICATION_SECRET>`

두 엔드포인트는 처리 결과와 무관하게 항상 200 을 돌려준다 (스토어 재시도 폭주 방지).
실패는 `eatlog.billing` 로거에만 남는다.

## 6. 검증

```bash
# 로컬 — 목 백엔드로 전체 흐름 확인
venv/Scripts/python.exe -m pytest -q --basetemp=.pytest_tmp tests/test_subscriptions.py

# 운영 — 구독 없는 계정
curl -H "Authorization: Bearer <access_token>" https://<BE 도메인>/v1/subscriptions/me
# → {"is_premium":false, ...}

# 운영 — 자격증명이 아직 없을 때 verify (503 이면 '안전한 실패'가 맞다)
curl -X POST https://<BE 도메인>/v1/subscriptions/verify \
  -H "Authorization: Bearer <access_token>" -H "Content-Type: application/json" \
  -d '{"platform":"android","product_id":"eatlog_premium_monthly","purchase_token":"x"}'
```

목 백엔드(`BILLING_BACKEND=mock`)의 토큰 규약 — 로컬에서 각 경로를 눌러 볼 때 쓴다:

| 토큰 접두사 | 결과 |
| --- | --- |
| `invalid-*` | 400 (스토어가 부정한 구매) |
| `down-*` | 503 (스토어 통신 실패) |
| `expired-*` | 어제 만료된 구독 (`is_premium=false`) |
| `canceled-*` | 해지 예약 — 만료 전까지 `is_premium=true` |
| 그 외 | 30일 뒤 만료되는 정상 구독 |

## 6.5 결제 503 이 날 때 — 원인부터 가른다

`POST /v1/subscriptions/verify` 가 503("결제 확인 서버에 연결할 수 없습니다")을 주면
설정 점검 엔드포인트로 원인을 바로 가릴 수 있다. 로그인 토큰만 있으면 된다.

```bash
curl -H "Authorization: Bearer <access_token>" https://<BE 도메인>/v1/subscriptions/health
```

```json
{
  "billing_backend": "store",
  "android": {"configured": true, "credentials_ok": true, "store_access_ok": true,
              "reason": null, "status": 404},
  "ios": {"configured": false, "reason": "not_configured"}
}
```

실제 구매 없이 점검한다 — 존재할 수 없는 구매 토큰으로 스토어를 호출해서,
"그런 구매 없음"(400/404)이 오면 권한이 정상이라는 뜻으로 읽는다.

| reason | 뜻 | 할 일 |
| --- | --- | --- |
| `null` | 정상 | 다른 원인을 보라 |
| `not_configured` | 설정값이 비어 있다 | Parameter Store 항목 이름·존재 확인 |
| `bad_credentials` | JSON 형식 오류 / `.p8` 불일치 / 토큰 발급 거부 | 값 다시 넣기 |
| `store_permission` | 스토어가 권한을 인정하지 않음 | **Play 는 권한 부여 후 반영에 최대 24시간** — 기다렸다 재확인 |
| `store_unreachable` | 네트워크·타임아웃·스토어 5xx | 잠시 후 재시도 |
| `mock_backend` | `BILLING_BACKEND=mock` | 운영이면 즉시 `store` 로 |

같은 `reason` 이 503 응답의 `error.details[0].reason` 에도 담긴다.

> 검증이 실패한 구매는 **거래를 닫지 않는다.** 원인을 고친 뒤 앱의 구독 화면에 다시
> 들어가면 스토어가 그 구매를 다시 전달해 자동으로 검증된다 — 재결제할 필요가 없다.
> 단, Android 는 3일 안에 확인되지 않은 구매를 Google 이 자동 환불한다.

## 7. 자주 나오는 실패

| 증상 | 원인 |
| --- | --- |
| verify 가 항상 503 | `/v1/subscriptions/health` 로 reason 을 먼저 확인 (§6.5) |
| verify 가 400 `not_found` | 토큰이 다른 패키지의 것이거나, Play 상품이 아직 활성화 안 됨 |
| 배포가 `줄바꿈 포함 값은 env_file에 넣을 수 없음` 으로 실패 | 자격증명을 여러 줄로 저장했다 — 한 줄로 압축해 다시 저장 (§3) |
| iOS 만 503 | `.p8` 개행이 깨짐(`\n` 이스케이프 확인), Key ID/Issuer ID 뒤바뀜 |
| 409 `already_linked` | 같은 영수증이 다른 계정에 붙어 있음 — 정상 동작(계정 돌려쓰기 차단) |
| 결제했는데 3일 뒤 환불 | Android 구매 확인(acknowledge) 실패 — 서비스 계정 권한 확인 |
