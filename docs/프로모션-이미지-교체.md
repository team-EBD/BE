# 프로모션 이미지 교체 (재배포 없이)

앱을 켤 때 뜨는 팝업과 튜토리얼 마지막 페이월의 이미지는 서버가 내려준다
(`GET /v1/promotions/active`). 내용은 전부 **Parameter Store 값**이라, 이미지를 바꾸는 데
앱 재배포(스토어 심사)도 서버 코드 변경도 필요 없다.

## 한눈에 보기

1. 새 이미지를 공개 HTTPS 주소에 올린다.
2. Parameter Store 의 `/eatlog/be/PROMO_IMAGE_URL` 과 `/eatlog/be/PROMO_ID` 를 바꾼다.
3. 약 1분 뒤 서버가 짧게 재시작하면서 반영된다. 앱은 다음에 켤 때 새 이미지를 받는다.

## 1. 이미지 올리기

- **로그인 없이 열리는 HTTPS 주소**면 어디든 된다 (S3 공개 객체, Firebase Storage 공개 URL 등).
  브라우저 시크릿 창에서 주소를 열어 이미지가 바로 보이는지 확인한다.
- 같은 파일 이름에 덮어쓰지 말고 **새 파일 이름**으로 올린다 (예: `promo-2026-11.png`).
  앱과 CDN 이 예전 이미지를 캐시하고 있을 수 있다.
- 권장 크기는 세로형 1080×1620 (2:3). 다른 크기도 되지만 아래 가로·세로 값을 실제 이미지에 맞춘다.
- 이미지 안의 문구가 실제 정책과 맞는지 확인한다 (예: "100회 무료" ↔ `FREE_CREDIT_LIMIT`).

## 2. Parameter Store 키

경로는 `/eatlog/be/<이름>`. 이름은 환경변수 이름 그대로이며 대문자로 적는다
(서버는 대소문자를 구분하지 않고 `app/core/config.py` 의 같은 이름 필드로 읽는다).

| 키 | 기본값 | 설명 |
| --- | --- | --- |
| `/eatlog/be/PROMO_IMAGE_URL` | 2026-10 출시 기념 이미지 (Firebase Storage, `app/core/config.py`) | 이미지 주소. **빈 값으로 두면 프로모션이 뜨지 않는다.** |
| `/eatlog/be/PROMO_ID` | `launch-100-free-2026-10` | 프로모션 식별자. **이미지를 바꾸면 반드시 같이 바꾼다** (아래 참고). |
| `/eatlog/be/PROMO_IMAGE_WIDTH` | `1024` | 이미지 가로(px). 정수. |
| `/eatlog/be/PROMO_IMAGE_HEIGHT` | `1536` | 이미지 세로(px). 정수. |
| `/eatlog/be/PROMO_TUTORIAL_IMAGE_URL` | 2026-10 출시 기념 가로형 이미지 (Firebase Storage) | **튜토리얼 마지막 페이월 전용** 이미지 주소(가로형 권장, 3:2). 빈 값이면 위 기본 이미지를 쓴다. 앱 시작 팝업에는 쓰이지 않는다. |
| `/eatlog/be/PROMO_TUTORIAL_IMAGE_WIDTH` | `1536` | 튜토리얼 전용 이미지 가로(px). 정수. |
| `/eatlog/be/PROMO_TUTORIAL_IMAGE_HEIGHT` | `1024` | 튜토리얼 전용 이미지 세로(px). 정수. |
| `/eatlog/be/PROMO_ALT_TEXT` | `Eat로그 출시 기념 — AI 분석 100회 무료` | 대체 문구 (스크린리더가 읽는다). |
| `/eatlog/be/PROMO_PLACEMENTS` | `launch,tutorial` | 노출 위치. 콤마 구분. `launch` = 앱 시작 팝업, `tutorial` = 튜토리얼 마지막 페이월. |
| `/eatlog/be/PROMO_ACTION` | `subscription` | 이미지를 눌렀을 때. `subscription`(구독 화면) / `url`(아래 주소를 웹뷰로) / `none`(동작 없음). |
| `/eatlog/be/PROMO_ACTION_URL` | (빈 값) | `PROMO_ACTION=url` 일 때 열 주소. |
| `/eatlog/be/PROMO_SHOW_TO_PREMIUM` | `false` | `true` 면 프리미엄 구독자에게도 보여준다. |
| `/eatlog/be/PROMO_ENABLED` | `true` | `false` 면 프로모션을 끈다. |

키가 없으면 표의 기본값이 쓰인다 — 바꾸려는 것만 만들면 된다.

### `PROMO_ID` 를 꼭 바꿔야 하는 이유

앱은 "오늘 보지 않기 / 7일간 보지 않기" 기록을 **`PROMO_ID` 별로** 저장한다.
이미지만 바꾸고 id 를 그대로 두면, 예전 프로모션을 닫은 사용자에게는 새 이미지가 보이지 않는다.
id 는 겹치지 않는 아무 문자열이면 된다 (예: `autumn-sale-2026-11`).
반대로 같은 프로모션의 오타만 고칠 때는 id 를 그대로 두면 이미 닫은 사용자를 다시 방해하지 않는다.

### 값이 잘못됐을 때 서버의 동작

- `PROMO_ACTION` 이 위 세 값이 아니면 `none` 으로 취급한다.
- `PROMO_ACTION=url` 인데 `PROMO_ACTION_URL` 이 비어 있으면 `none` 으로 취급한다.
- `PROMO_PLACEMENTS` 에 없는 위치에서는 프로모션이 뜨지 않는다 (비우면 어디에도 뜨지 않는다).
- 가로·세로가 0 이하면 1080×1620 으로 내려준다.
- `PROMO_IMAGE_WIDTH/HEIGHT`, `PROMO_ENABLED`, `PROMO_SHOW_TO_PREMIUM` 에 숫자·불리언이 아닌
  값을 넣으면 **서버가 기동하지 못한다.** 숫자는 숫자만, 불리언은 `true`/`false` 로 적는다.

## 3. 끄기

`/eatlog/be/PROMO_ENABLED` 를 `false` 로 둔다. (`PROMO_IMAGE_URL` 을 비워도 같은 효과.)
앱은 프로모션이 없으면 팝업을 띄우지 않고, 튜토리얼 페이월은 앱에 내장된 화면을 보여준다.

## 4. 반영 시점

Parameter Store 값을 바꾸면 **약 1분 뒤** 서버가 새 값을 읽어 **짧게 재시작**하면서 반영된다.
코드 배포(GitHub Actions)는 필요 없다. 앱은 켤 때 한 번 조회하므로, 이미 켜져 있는 앱은
다음에 켤 때 새 프로모션을 본다.

확인 방법 (로그인 토큰 필요):

```
GET /v1/promotions/active?placement=launch
→ {"promotion": {"id": "...", "image_url": "...", ...}}   # 보여줄 것이 있을 때
→ {"promotion": null}                                      # 없을 때 (오류가 아니다)
```

프리미엄 계정으로 조회하면 `PROMO_SHOW_TO_PREMIUM=true` 가 아닌 한 항상 `null` 이다 —
확인은 무료 계정으로 한다.

## 5. 무료 AI 사용권 횟수 바꾸기

`/eatlog/be/FREE_CREDIT_LIMIT` (기본 `100`, 정수). 무료 사용자가 평생 쓸 수 있는 AI
호출(분석 + 추천, 성공한 것만) 횟수다. 반영 방식은 위와 같다.

- 이 한도는 `AI_PREMIUM_GATE=true` 일 때만 실제로 막는다. `false` 면 기능별 일일 한도
  (`ANALYZE_DAILY_LIMIT` / `RECOMMEND_DAILY_LIMIT`)가 적용되고, 이 값은
  `GET /v1/usage/daily` 의 `free_credits` 표시에만 쓰인다.
- 앱 화면의 숫자와 한도 초과 안내 문구는 서버 값을 따른다. 다만 **프로모션 이미지 안에 적힌
  숫자는 자동으로 바뀌지 않으므로** 횟수를 바꾸면 이미지와 `PROMO_ALT_TEXT` 도 함께 바꾼다.
- 값을 낮추면, 이미 그 횟수 이상 쓴 무료 사용자는 바로 한도 초과가 된다.
